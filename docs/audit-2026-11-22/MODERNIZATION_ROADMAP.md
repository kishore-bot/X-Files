## Test coverage and additions

- Seventeen common Kotlin tests and one Android host test file cover formats, PDF planning, search, book behavior, archive tree, Tidy and Fily rules. CI invokes the shared host suite. Add delayed renderer, model generation, retry, Flow, persisted-state and concurrent callback tests.
- Kotlin Android benchmark sources cover baseline journeys, startup and the reader. The public tree lacks generated baseline profile text at the documented destination. Add SAF failure and permission integration, OCR lifetime, AppFunctions revocation, offline speech, release FFmpeg decoding and usability on phone and tablet.
- Three Rust UniFFI-facade integration test files and one MCP stdio integration file complement in-crate tests. Add real Kotlin-to-native handle ownership tests, interruption and disk fault tests, property tests for format boundaries, and parser/JNI fuzzing with synthetic fixtures.
- Training includes three Python test files. Freeze a held-out deck with hashes, report per-metric denominators, and verify end-to-end Android grammar, tools and permission policy separately. Add sustained native memory, cancellation and input-stress benchmarks.

## Fily measurement after approval

Use the same release phone, OS, model and prompt checksums, tool grammar, output cap, fixture library and thermal conditions. Collect at least 30 paired cold and 30 warm prompts across tool commands, retrieval, excerpts and refusal. Compare cold load separately from p50/p95 first-token latency, speech-end to first audio, and decode tokens per second after first token. Track prefill and reused tokens, actual CPU/GPU backend and idle, loaded, peak and post-close app PSS and native heap. Include repeated turns and model close. [Native measurements](../../engine/crates/fily-inference/src/android.rs#L257)

Run the existing harness on the NVIDIA GPU with the same frozen split and verify actual offload. Keep all seven quality metrics and per-family denominators. The harness disables prompt caching and uses a schema, so validate app KV behavior, GBNF and tool execution independently. Numeric grounding metrics need human-reviewed semantic and citation checks. Proposed gates allow at most 5% regression in p95 first-token time and median throughput, 10% maximum peak PSS growth, and two percentage points quality loss on metrics with adequate samples. Establish absolute budgets from the baseline. [Harness](../../training/eval_harness.py#L110) · [Macrobenchmark](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview)

Use the requested WSL tree and JDK/SDK paths, with low-memory flags `--no-daemon --max-workers=1 -Pkotlin.compiler.execution.strategy=in-process`. Include wrapper, Android modules, Rust, FFmpeg and script inputs for the chosen phase. The former `:shared` lint exclusion has no corresponding module. Find the current task and run release lint in a separate gate. [Settings](../../settings.gradle.kts#L17)
