# Data structures and performance

N is entries, H matches, P postings visited, k returned results, W and h image dimensions. Source costs exclude provider and native runtime variance.

| Path | Current cost and improvement |
|---|---|
| SAF traversal | BFS uses O(N) row work, retained entries and provider IO before ordering. Retain BFS. Compare wide and deep trees, tracking provider calls and time to first usable result. Incremental delivery needs snapshot consistency. [Folder scan](../../core/documents/src/main/kotlin/com/xfiles/core/documents/FolderRepository.kt#L89) |
| Filename ranking | Trigram and bounded edit-distance scoring of each candidate, then full hit ordering. O(N × score cost + H log H) and O(H) hits. If k is small and the sort is hot, bounded top-k costs O(H log k) and O(k) hit storage. Verify tie ordering and diacritics at 1k, 10k and 100k names. [Filename index](../../sharedLogic/src/commonMain/kotlin/com/xfiles/documents/search/FileNameIndex.kt#L30) |
| Full-text search | Approximate O(P + H log H) plus snippet IO and whole index serialization on saves. Fix commit and retry semantics first. Time tokenization, ranking, serialization, mutex wait and scans separately before adding incremental persistence or top-k. [Rust query](../../engine/crates/document-search/src/index.rs#L364) |
| Similarity grouping | Band buckets and union-find. O(N × bands + comparisons × near-constant union cost), plus bucket ordering. Crowded bucket work is bounded. Compare recall and query time with brute force on small and collision-heavy corpora. [Grouping](../../engine/crates/document-tidy/src/similar.rs#L34) |
| PDF cache and search | Access-order page lookup O(1) typical but count limit permits large native bitmap use. Search is O(pages) with extra raster and recognition work on a zero-hit fallback. Use size and session-aware caching plus image-only OCR. Compare digital hit/miss, scanned, mixed and repeated-switch timing and peak PSS. [Page cache](../../feature/reader/src/main/kotlin/com/xfiles/feature/reader/domain/PdfPagesUseCase.kt#L26) · [Search](../../core/documents/src/main/kotlin/com/xfiles/core/documents/AndroidPdfDocument.kt#L317) |
| Scan enhancement | Sauvola sliding-window processing is O(W × h), with O(W) column statistics plus image output. Retain the algorithm. Measure copies into JNI/UniFFI, decoder overhead and peak memory before using tiles or SIMD. [Sauvola](../../engine/crates/document-imaging/src/sauvola.rs#L24) |
| Fily | Fixed context budget, reusable prompt prefix, batched decode and serial generation. Compare cold startup, warm matching prefix and changed context. Count prefill/reused tokens, backend and decode time. [Native timing](../../engine/crates/fily-inference/src/android.rs#L257) |
| Media and desktop | FFmpeg cost depends on samples, codec and channels. MCP load depends on concurrent jobs, format expansion and output sizes. Benchmark audio sync, underruns, 30-minute memory drift, job queue wait, cancellations and partial writes. [Decoder](../../ffmpeg/rust/src/decoder.rs) · [Jobs](../../engine/crates/xfiles-mcp/src/jobs.rs#L63) |

Measure cold and warm startup, first content paint, PDF navigation, search, archive, scanning, playback and Fily on the same fixtures and release variants. Separate instrumented memory, energy and timing runs. Capture p50 and p95 frame and wall time, peak/steady PSS, native and Kotlin heaps, GC, IO, thermal and battery indicators. Glass effects need contrast and frame-time checks on phones and tablets. Protect borrowed or pooled buffers with a provable owner before adopting them.
